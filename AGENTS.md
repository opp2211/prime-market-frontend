# AGENTS.md

- Всегда отвечай пользователю на русском языке.
- Стек проекта: frontend, React, Vite, npm, js.
- Перед началом задачи сначала изучи router, layout, navigation, API layer и связанные страницы.
- Не переписывай проект с нуля; встраивайся в существующую архитектуру и UI-паттерны.
  ripgrep (`rg`) отсутствует в окружении: сразу используй доступные штатные средства (`git grep`, `grep`, `find`, PowerShell/IDE search).
- Перед изменениями, затрагивающими backend API, сначала сверяйся с актуальным backend contract artifact в соседнем backend-репозитории: `../prime-market-backend/api-contract/openapi.json`.
  Это source of truth для backend API; не трать время на поиск контракта по файловой системе, если путь уже известен.
  Не полагайся только на старые assumptions, DTO, прошлые отчёты или "как раньше работало".
  Если контракт и текущий frontend-код расходятся, либо явно следуй контракту, либо честно укажи расхождение в отчёте, если задача не про исправление этого места.
- Не дублируй бизнес-логику на фронте, если её уже может явно отдать backend.
- Для новых экранов и флоу всегда делай loading / empty / error states.
- При создании или изменении интерфейса ориентируйся на единое правило breakpoint: до `1024px` — мобильная версия, от `1024px` включительно — десктопная версия.
- Переиспользуй существующие компоненты, стили и helper-функции, если они уже есть в проекте.
- Стили пиши профессионально и локально: `src/styles/globals.css` используй только для reset/base-стилей, CSS-переменных темы, типографики, общих layout-примитивов и действительно переиспользуемых utility-классов. Стили конкретных страниц, виджетов и крупных блоков выноси в colocated CSS Modules рядом с компонентом (`Component.module.css`) и подключай через `import styles from './Component.module.css'`.
- При редизайне страницы не добавляй новые page-specific селекторы в `globals.css`. Если трогаешь страницу или блок, постепенно переноси связанные старые глобальные классы в CSS Module этой страницы/блока, обновляй JSX на `styles.*` и удаляй ставшие неиспользуемыми правила из `globals.css` в той же задаче, если это безопасно.
- Не делай отдельную большую задачу "переписать весь globals.css" без прямого запроса. Уходи от большого `globals.css` инкрементально: страница за страницей, блок за блоком, с проверкой UI после каждого законченного изменения.
- Перед сдачей прогоняй хотя бы релевантный lint для изменённых файлов и `build`, если задача затрагивает UI или routing.
- После успешного выполнения каждой законченной задачи и прохождения релевантных проверок обязательно делай `git commit`; не коммить сломанные изменения.
- Сообщение коммита должно быть на русском языке и соответствовать Conventional Commits.
- Не заявляй, что всё работает, если сам это не проверил.
- В конце задачи давай короткий отчёт: изменённые файлы, что сделано, что проверено, закоммичены ли изменения, hash коммита, commit message, какие ограничения остались.
